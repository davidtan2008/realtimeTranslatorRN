# 06 功能与效果打折扣的点 · React Native

对照：各端**原生对译**（iOS Duiyi / Android / 鸿蒙）。RN 再叠一层折扣。

---

## 1. 总表

| 能力 | 原生对译 | RN v1 | 用户能感觉到 |
| --- | --- | --- | --- |
| 字幕延迟 | 端侧极限 | +胶水；差的一端更明显 | 口型对不齐 |
| 面对面倒字 | 系统 UI 线程 | Reanimated，差则掉帧 | 平放时卡 |
| 语言能力 | 该端 Catalog | 同，但探测多一跳 | 启动稍慢 |
| 同传 TTS 路由 | 原生精确 | 事件晚一拍 | 拔耳机后可能多读半句 |
| 总结 | 该端模型 | 同 | 不应差 |
| 任务 | 该端 DB | SQLite 对齐 | 不应差 |
| 鸿蒙 | 原生 Kit | RNOH 二期或不发 | 可能根本没这包 |
| iOS 翻译 | SwiftUI 锚点 | 透明 UIView 锚点 | 换页偶发要重新 prepare |
| 包体 | 系统模型 | RN 运行时 + 原生 | 安装包更大 |

听写 / 翻译质量上限 = 该端原生上限（见各端 `06`）。RN **不能**用胶水补双路 ASR。

---

## 2. 手感

目标：iOS RN 与 Duiyi 原生接近（同一 Analyzer）。Android RN 与 Android 原生接近。若 RN Android 明显慢，优先查事件合并，而不是换云 ASR。

允许的折扣：首包比原生多 50–100 ms。不允许：每句明显顿挫、错序 final。

---

## 3. 发布形态折扣

建议商店策略（产品必须选一个）：

1. **只发原生包**（iOS / Android / 鸿蒙各一个），RN 仅内部用于快速改历史 / 设置。  
2. **只发 RN 包**覆盖 iOS+Android，鸿蒙走原生。  
3. 双包同时上 = 用户混乱，默认否决。

文档默认按 2 讨论 iOS+Android RN，鸿蒙以原生为准。若选 1，RN 仓库仍作设计与共享 Domain 测试床。

---

## 4. 必须对齐的 P0

与 Android `06` 第 10 节相同。另外：

- JS 不得在无任务时 start 听写  
- App 进后台必须 stop  
- Catalog 灰掉不可用语言，三端同一套 Copy 语义  

---

## 5. 不要用 RN 承诺的句子

禁止商店文案：「一套代码，三端体验完全一致。」应写：「界面统一，听写与翻译使用各系统本机能力，可用语言因设备而异。」
